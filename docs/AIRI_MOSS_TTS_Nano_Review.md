# AIRI · MOSS-TTS-Nano inference review

**Decision.** Keep fixed sampling, WASM and a 75-token chunk target as the baseline. First fix worker initialization and the audio path. Both sampling choices currently execute fixed sampling, a changed thread count can break built-in voices, and AIRI returns only the left channel of the codec's stereo output. These findings change which experiments are worth running.

Reviewed AIRI main at [`4ead5606`](https://github.com/dasilva333/airi/commit/4ead5606977c7947c122743b23dee8dcd011259c), the [original research report](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/docs/research-moss-tts-nano-report.md), the [provider proposal](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/docs/proposal-moss-tts-nano-provider-unified-webgpu.md), the [upstream Reader](https://github.com/OpenMOSS/MOSS-TTS-Nano-Reader/blob/c3b2333b88e0f062ca49d403540a169609354d93/extension/browser_onnx_runtime.js), [Python ONNX runner](https://github.com/OpenMOSS/MOSS-TTS-Nano/blob/8b7bcc9341b3b4ef3a3a58ba1338a7d85ff133eb/infer_onnx.py) and published model metadata. Isolated probes exercised the checked-in JavaScript and conditioning functions. Browser RTF, first audible playback, speaker similarity, and GPU placement remain unmeasured.

## 1. What the four settings actually do

| Setting | Current behavior | Recommended interface |
|---|---|---|
| Attention backend | AIRI passes the value into generation and the worker discards it. The Reader-derived session factory selects WASM for every graph. Upstream applies its attention selection while constructing the model for ONNX export. | Remove the selector, registry default and request field. Ignore the old persisted key. A read-only “Running on CPU · WASM” line can share the thread status. |
| Sampling | Both UI values resolve to fixed sampling. An explicit recognized mode takes precedence over the incoming sampling boolean. | Expose **Fixed** by default and **Full sampling** and **Greedy** under Advanced. Use one typed mode from UI through worker. Migrate legacy `dynamic` to `fixed` to preserve the sound and cost existing users were actually getting. Make full an explicit choice. |
| CPU threads | Load initializes ORT with 4 requested. A different generation-time count invalidates the runtime's preparation key and clears its state. ORT initializes its own thread pool once. | **Auto** plus an explicit count, resolved before the first session. Retain saved numeric choices. Show resolved startup count and isolation status. Apply changes at an idle boundary by replacing the worker. |
| Max text tokens | Limits target-utterance segments in SentencePiece tokens. The splitter already prefers sentences, then clauses, then token-budget cuts. Each segment reuses the same speaker prompt and starts a new prefill. | Keep **75** and move the setting under Advanced as **Target text tokens per segment**. Replace the current hint about reference-audio conditioning. |

### Sampling cost on the actual download

| Mode | Execution for one continuing audio frame | Implication |
|---|---|---|
| Fixed | One local sampled-frame ORT call with random draws supplied by JS, then one global decode call. The exported graph fixes the sampling parameters. | Best-supported latency baseline and upstream default. “Fixed” describes the parameters. Repeated renders can sound different. |
| Full | One cached local call for continue/end and one per audio codebook, with logits sampled in JS. At 16 codebooks this is 17 local calls plus the global decode. | More dispatches, JS sampling and yields. Useful for sampling experiments. A 17× increase in local call count does not predict a 17× increase in total RTF. The current UI exposes no temperature or top-p overrides. |
| Greedy | Uses argmax. The runtime supports a fused greedy graph, but the published TTS metadata and AIRI download list omit it. This bundle takes the cached local path. | Useful as a repeatability baseline. Compare latency against fixed before calling it fast. Listen for repetition, missed endings and flat prosody. |

The non-cached local decoder is an alternative when the cached graph is absent. AIRI's fallback references an undeclared `nextTextToken`. The shipped bundle supplies the cached graph. Reject unsupported alternative bundles clearly, or repair and exercise the fallback before claiming support for them. Sources: [generation branches](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L2128), [fallback](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L2231), [download list](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_model_store.js#L7), [published graph list and codebook count](https://huggingface.co/OpenMOSS-Team/MOSS-TTS-Nano-100M-ONNX/blob/main/tts_browser_onnx_meta.json), [manifest defaults](https://huggingface.co/OpenMOSS-Team/MOSS-TTS-Nano-100M-ONNX/blob/main/browser_poc_manifest.json).

### Why changing threads can break the first utterance

On a changed key, `configure()` clears the manifest, tokenizer and session map without explicitly releasing those sessions. Built-in voice lookup then runs before the manifest is reloaded. In an isolated test, configuring a prepared runtime from 4 to 2 cleared its preset list and a request for the previously present Trump preset failed with `Voice preset not found or empty: Trump`. A raw clone can take a different path because loading its encoder first reloads the manifest. The defect depends on the voice path and can escape a settings smoke test. Sources: [runtime reset](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L1309), [lookup order](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L2427), [worker load and generation](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/worker.ts#L64).

Share Ming's thread-resolution logic in a lightweight common module. Resolve 1 without isolation or on one logical core. Otherwise Auto requests `min(4, max(2, floor(hw / 2)))`; bound a valid manual override to hardware and 32. Pass this through **both** settings preload and lazy load. Key worker reuse on effective count so two equivalent settings do not trigger a reload. A fresh worker gives ORT a new WASM environment. Keep one RPC binding per worker, serialize setting changes with generation, and clear stale codec/status data on teardown. The ORT 1.24.2 source places the global intra-op thread count in one-time runtime initialization. Recreating sessions in the same initialized worker is insufficient. Sources: [Ming resolver](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/libs/inference/adapters/ming3.ts#L90), [lazy load](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/stores/providers/registry/speech.ts#L531), [preload](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/stores/providers/registry/speech.ts#L627), [ORT Web 1.24.2 initialization](https://cdn.jsdelivr.net/npm/onnxruntime-web@1.24.2/lib/wasm/wasm-core-impl.ts).

### Where the chunk target matters

Shorter segments repeat the reference prefix, reset prosody, and insert silence more frequently. Longer ones amortize prefill but delay the first complete segment in buffered mode and risk running into the per-segment generation ceiling. The published 375-frame ceiling at 12.5 Hz is about 30 seconds of generated audio per segment. Check frame-cap terminations and missing final words when experimenting with larger targets. The join heuristic currently inserts 400 ms after segments of four or fewer whitespace-delimited words and 240 ms otherwise. This can misclassify long Chinese segments and place a sentence-length pause inside a forced clause split. Keep boundary type with each segment and tune pauses for actual sentence, clause and hard-cut boundaries. The speaker prompt is reused on every segment. Any improvement or degradation in perceived identity across segments needs listening evidence. Sources: [pause heuristic](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L1815), [chunk loop](https://github.com/dasilva333/airi/blob/4ead5606977c7947c122743b23dee8dcd011259c/packages/stage-ui/src/workers/moss/browser_onnx_runtime.js#L2462), [upstream CLI defaults](https://github.com/OpenMOSS/MOSS-TTS-Nano/blob/8b7bcc9341b3b4ef3a3a58ba1338a7d85ff133eb/infer_onnx.py#L83), [codec metadata](https://huggingface.co/OpenMOSS-Team/MOSS-Audio-Tokenizer-Nano-ONNX/blob/main/codec_browser_onnx_meta.json).

## 2. Disposition of report sections 4 and 5

| Original item | Finding and action |
|---|---|
| Rank 1 · reference conditioning | Shipped with −45 dB threshold, 150 ms padding, 50 ms fades and −3 dB peak. Fix the all-quiet early return and the reversed trailing fade. They can compromise an otherwise valid quality comparison. |
| Rank 2 · prompt-code cache | Works for previously encoded uploaded profiles. Upload computes SHA-256, but the read/write key is profile ID, with unversioned codes in metadata. Bundled starter WAVs still go through preprocessing and encoding per request. Manifest presets already contain codes. Extend caching to starters and validate code provenance. |
| Rank 3 · resampling | Shipped. Uploaded references use a real offline render when the sample rate or channel count differs and are packed channel-major. Validate positive codec metadata at load and retire the silent 16 kHz/mono fallbacks for this export. |
| Rank 4 · worker host | Still open as a reliability task. Reuse fatal-error cancellation, teardown, bounded restart and lazy reload. Ordinary cancellation should leave a healthy worker usable. The worker already runs on WASM, so a GPU promotion or GPU memory reservation has no purpose here. |
| Rank 5 · memory estimate | The 400 MiB entry exists. It is an advisory constant. No MOSS GPU allocation is happening. Measure process/WASM memory for the active sessions before using this estimate for admission control. |
| Q1 and Q6 · format and channels | The official codec JSON specifies 48,000 Hz, 2 channels, stride 3,840 and 16 quantizers. The input tensor is correctly planar `[1, 2, frames]`. Output loses the right channel at the worker-to-adapter boundary. |
| Q2 and Q5 · storage and sync | UI and reconciler already share both localforage names, keyed by profile ID. The remote layout is `assets/voice-profiles/{id}.json` plus audio. Reconciliation fills missing pairs and serializes metadata wholesale, so codes may travel inside JSON. A local metadata entry with a missing blob can escape download repair. Keep the layout, validate or regenerate derived codes, and repair partial pairs. Persistence is per origin/storage bucket. Request it from the window after a user saves a profile and check the result; the worker's guarded, best-effort call does not establish a grant. |
| Q3 · WebGPU | WASM/SIMD is the actual Reader and AIRI route. Native Python CPU/CUDA support says nothing about browser node placement. Profile individual exported graphs on the target browsers before exposing an execution-provider selector. |
| Q4 · reference duration | AIRI targets 1–15 s for active input. A shorter source can remain shorter than one second. A fully below-threshold signal bypasses the maximum. The function decodes and may offline-render the full upload before trimming. Distinguish a user-facing duration policy, an input resource limit and the codec's architectural limits. |

### Benchmark that can select a default

1. **Establish the baseline.** On Apple Silicon Chromium and a representative Windows Chromium device, record CPU, browser, isolation, requested/effective startup threads, ORT version and model revisions. Split first download, warm OPFS/new worker and already-loaded generation. Use a built-in, a bundled starter and a custom clone with cold and warm prompt codes. Include an unisolated one-thread run.
2. **Measure throughput.** Hold text, prompt codes and the 75-token target constant. Sweep fixed at 1/2/4 threads, then compare fixed/full/greedy at the best thread count. Repeat sampled modes across draws and record generated frame counts. Report median and spread, wall-clock generation time divided by output duration (RTF, lower is better), ms/generated frame, prefill, local/global decode, codec and reference preparation. Report inserted silence separately so extra pauses cannot appear to improve synthesis speed.
3. **Measure conversation latency.** Record request-to-first-PCM, request-to-first-audible and request-to-complete WAV separately. Include one short chat reply and a multi-segment passage. A worker timestamp alone misses buffering and intentional playback holds.
4. **Listen for cloning and prosody.** Compare matched 3/6/10/15-second excerpts of the same clean reference and 50/75/100-token budgets as independent experiments. Use English and Chinese, punctuation, a long sentence and a paragraph. Randomize playback, match loudness, and score speaker likeness, intelligibility, natural phrasing, boundary glitches, repeats and missing endings. Record frame-cap hits; ASR error and speaker-embedding similarity can supplement listening. Promote a changed default only if its improvement survives the repeat runs.

**Scope of verification.** The mode-resolution, prepared-runtime reset, built-in lookup failure, quiet-input duration/gain and fade examples were exercised without model weights. Stereo loss, graph dispatch counts, storage behavior and load order were established by tracing source and metadata. No end-to-end audio was generated or judged in this review.
